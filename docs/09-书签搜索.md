# 书签搜索

> 2026-10-09：用户确认本轮先定规格再实现；两项决策已按推荐方案确认（顶栏图标 + `/` 唤起、默认全部书签）。对应候选版 1.2.0。
> 状态：**已实现并通过全部质量门**（314 测试全绿，覆盖率门禁通过）。

## 一、范围与合规边界

只做**本地书签的过滤式搜索**，这是 `docs/01` 调研中唯一判定为低风险的搜索形态（C7 的书签部分）。

- ✅ 在已加载的书签树内按标题 / URL 过滤，纯客户端计算，零网络请求、零新权限。
- ❌ 不接入任何外部搜索引擎 URL 拼接、不做引擎切换、不做 omnibox（`chrome.omnibox`）关键字。
- ❌ 不搜历史记录、不搜已打开的标签页——那需要 `history` / `tabs` 的新用途，与「权限最小化」和单一用途定位冲突。
- 商店描述统一措辞为「filter / find your bookmarks」，不出现「search engine」。上架前按 `docs/04` 清单复核。

## 二、用户操作

### 入口

顶栏新增放大镜按钮（位于「撤销删除」左侧），点击后展开输入框：

- 展开时输入框**接管面包屑的位置**并自动聚焦；面包屑、撤销、多选按钮暂时隐藏，主题与设置按钮保留。
- 快捷键 `/` 在非输入态下唤起（沿用既有 `App.vue` 的全局 keydown 分发，输入/对话框/侧栏内不触发）。
- 不使用 `Ctrl/⌘+K`：该组合在新标签页被浏览器地址栏占用。

### 输入

- 输入即搜，120ms 防抖；去首尾空白后长度 ≥ 1 才产生结果。
- 输入框右侧「清空」按钮（有内容时出现）；`Esc` 优先清空内容，已为空则收起输入框并把焦点还给顶栏搜索按钮。
- 输入框旁一个范围切换 chip：**全部书签**（默认）/ **仅当前目录**。仅对本次搜索生效，关闭后重置为「全部书签」。

### 结果视图

搜索处于激活态且有结果时，主区由 `BookmarkGrid` 切换为结果视图：

- 沿用网格卡片样式，虚拟滚动同样生效（复用 `BookmarkGrid`，见第五节）；方向键在结果间移动焦点，Home / End 跳到首尾——与主网格共用同一套 roving tabindex。
- 每张卡下方补一行**所在文件夹路径**（如 `书签栏 / 开发 / 前端`），路径可点击 → 退出搜索并跳转到该文件夹。
- 书签卡片：点击/中键/Ctrl 点击的打开行为与主网格完全一致；右键菜单沿用 `bookmark-actions` 全套（复制、编辑、二维码、删除）。
- 文件夹卡片：点击 → 退出搜索并进入该文件夹（不再悬停弹出级联面板，结果视图下面板会跨越目录，容易误触）。
- 标题栏显示 `{n} 条结果`；结果超过上限时底部提示「另有 {n} 条未显示，请补充关键词」。

### 退出

- `Esc`、清空按钮、点击路径 / 文件夹卡片、切换目录，都会结束搜索并回到原目录视图。
- 搜索激活时禁用多选入口（多选只作用于当前目录，与跨目录结果语义冲突）；若用户从结果卡片右键选「多选」，则先退出搜索、跳转到该项所在目录并选中该项——复用 `selection.start(node)` 的既有能力。
- 结果视图内不响应拖放（跨目录落点没有明确语义），网格空白区拖放同样禁用，避免误移动。

## 三、匹配与排序规则

归一化：标题与 URL 去首尾空白、折叠连续空白、转小写；URL 去掉协议与末尾斜杠后再比对。

- **分词**：按空白切成多个词元，全部词元都要命中（AND）；单字/单词都触发搜索（中文不做 2 字门槛）。
- **字段**：标题（书签与文件夹）+ URL（仅书签，host 与 path 都参与）。
- **打分**（高到低）：

| 命中位置            | 分值 |
| ------------------- | ---- |
| 标题以完整查询开头  | 100  |
| 标题以某个词元开头  | 60   |
| 标题包含词元        | 40   |
| 文件夹标题命中      | 30   |
| URL host 以词元开头 | 25   |
| URL 包含词元        | 20   |

- 一个词元只取它命中的最高一档，多个词元累加；标题再以**完整查询**开头时额外加权 40（单关键词时即 `60 + 40 = 100`，正好落在表里的第一档）。
- **同分稳定排序**：按树的深度优先序（索引顺序）保持，不做层级加权——用户熟悉的是书签管理器里的自然顺序。
- **上限**：`MAX_SEARCH_RESULTS = 200`，超出截断并显示剩余数量。
- 不做拼音、模糊（编辑距离）、正则、布尔语法、字段限定符（`title:` 之类）。这些留给后续按反馈决定。

## 四、边界与失败处理

- 树为空 / 仍在首次加载：不显示搜索结果，沿用既有 loading 与加载失败重试视图。
- 查询无命中：显示空态文案 + 「清空」入口；不显示 0 条结果网格。
- 搜索期间书签在别处被改动（同步、原生管理器）：结果视图随 `bookmarks.tree` 自动重算；已删除的项自然消失，不做快照重试。
- 搜索是纯内存计算，没有失败态；不需要 `ui.toast` 或错误文案。
- 不可移动 / 受管理的目录照常出现在路径与结果中，操作限制沿用 `isMovableBookmark` 的既有判定。
- 查询词与范围**不持久化**，不写入 `storage`；每次打开新标签页都是干净状态。

## 七、性能预算

索引随 `bookmarks.tree` 变化惰性重建（展平一次，复用 `tree-utils.flatten`），5000 节点目标 < 10ms；单次查询单遍扫描，目标 < 5ms。防抖 120ms 保证连续输入不重复计算。结果区复用虚拟滚动，挂载节点数不随结果量线性增长。

## 八、决策记录

1. **入口形态**：采用顶栏图标 + `/` 唤起（保持新标签页极简，不常驻输入框）。否决玻璃卡顶部常驻输入框。
2. **默认范围**：采用全部书签，输入框旁可切到「仅当前目录」，关闭搜索后重置。

实现与规格的两处偏差（均为实现细节，不改变行为）：

- 打分里的「文件夹标题命中 30」只对**包含**生效；文件夹标题以词元开头仍按 60 计，避免层级目录在强命中时被压低。
- 路径里不显示浏览器虚拟根（id=0），它不算一层目录。
