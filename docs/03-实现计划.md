## Phase 0 — 脚手架（半天）

**任务**
1. Vite + Vue 3 + TS 脚手架（`npm create vite@latest`，vue-ts 模板）
2. 接入 Tailwind（v4 `@tailwindcss/vite`）、路径别名 `@/`
3. `manifest.config.ts` 生成 MV3 manifest：仅 `chrome_url_overrides.newtab` + 五项权限，无 host_permissions、无 content_scripts
4. 扩展构建方案：优先 `@crxjs/vite-plugin`（若与最新 Vite 不兼容，退回手动多入口构建 + manifest 复制脚本——**此为已知风险点**）
5. `@types/chrome`、ESLint、Prettier
6. 临时占位图标（正式 logo 后补）

**验收**
- `加载已解压的扩展程序` 后打开新标签页，显示 Vue 渲染的空白页
- 控制台无错误；manifest 权限仅五项

**完成记录（2026-08-27）** ✅
- 版本：Vue 3.5.41 / Pinia 4.0.3 / Vite 8.2.2（rolldown）/ TypeScript 5.9.3 / Tailwind 4.3.3 / ESLint 10 / vue-tsc 3.3.11
- 构建方案：**手动模式**（crxjs 在 Vite 8 下半兼容，见风险表）；`pnpm build` 产物含 manifest.json、_locales、icons、HTML/CSS/JS
- 命令：`pnpm dev`（纯 Web 预览，无 chrome API）/ `pnpm watch`（扩展开发联动：重开后到 chrome://extensions 刷新扩展）/ `pnpm build` / `pnpm lint` / `pnpm typecheck`
- 占位图标：`node scripts/gen-placeholder-icons.mjs`（纯色叶绿 PNG，Phase 4 换正式 logo）
- 加载验证方式：`chrome://extensions` → 开发者模式 →「加载已解压的扩展程序」→ 选 `dist/` 目录 → 新开标签页

## Phase 1 — MVP 核心展示（2~3 天）

覆盖：A1 A2 A3 A5 A6 A9 B1 B4 G5 F1 F8

**任务**
1. `lib/chrome-bookmarks.ts` / `chrome-storage.ts` Promise 封装 + 类型定义（**先写测试**）
2. `lib/tree-utils.ts` 纯函数：树→扁平、按 id 查节点、计算路径（**测试重点**）
3. `stores/bookmarks.ts`：加载树、监听 `chrome.bookmarks.onCreated/onRemoved/onChanged/onMoved` 自动刷新
4. `stores/settings.ts`：主页文件夹 id、打开方式、主题；`chrome.storage` 持久化 + 变更监听
5. 组件：BookmarkGrid / BookmarkCard / FolderTree / Breadcrumb / ContextMenu / FolderPopup
6. **FolderPopup 悬停弹窗（A9）**：`useHoverIntent` 组合式函数（延迟 250ms 出现 / 进入弹窗保持 / 离开 200ms 宽限收起 / Esc 与滚动关闭）；子文件夹级联悬停展开；视口边缘自动翻转；max-height 滚动；悬停懒渲染
7. **毛玻璃设计令牌（F8）**：Tailwind 封装 `.glass` / `.glass-strong` 工具类（半透明底 + `backdrop-blur` + 描边 + 投影），应用到卡片/弹窗/侧栏/菜单
8. 右键菜单：设为主页(A2)、复制 URL(B1)、编辑(B4)、删除+确认(B4)
9. 打开方式设置(G5)：新标签页/当前页（弹窗内书签同样遵循）
10. 暗黑模式(F1)：浅/深/跟随系统，`data-theme` + Tailwind `dark:` 变体，与毛玻璃组合适配

**验收**
- 右键任一文件夹设为主页后，新开标签页展示该文件夹书签
- 悬停文件夹 ~250ms 弹窗出现；移入弹窗不消失；移开 200ms 内收起；子文件夹可级联展开；弹窗在视口边缘自动翻转不溢出
- 点击弹窗内书签按 G5 设置的打开方式生效
- 编辑/删除在浏览器原生书签管理器中立即可见（真实写回，非本地状态）
- 浅色/深色 × 毛玻璃组合下文字对比度可读

## Phase 2 — 交互增强（2 天）

覆盖：A4 B3 B2

## Phase 4 — 打磨与上架（1~2 天 + 审核周期）

**任务**
1. 错误兜底：书签 API 异常、空文件夹态、超大树（5000+ 书签）渲染性能（必要时虚拟滚动）
2. 毛玻璃性能验证：大量卡片 + 多层弹窗场景的 `backdrop-filter` 渲染开销；必要时分层模糊或提供「关闭模糊」降级开关
3. 正式 logo + 图标三尺寸
3. 商店素材：中英文描述、截图（5 张内）、权限用途说明、隐私声明（不收集数据）
4. `vite build` 产物 zip；Chrome Web Store 提审
5. Edge Add-ons 后台提审（同一 zip）

**验收**
- 两家商店过审上线

## 测试策略

- **单元（Vitest）**：`lib/*`（chrome 封装 mock、tree-utils 纯函数）、`stores/*`（状态流转）、`useHoverIntent`（用 fake timers 测延迟出现/宽限收起/进入保持）
- **组件（@vue/test-utils）**：BookmarkCard/ContextMenu/FolderPopup 等交互组件
- **TDD 顺序**：Phase 1 的 lib/stores 层先写测试（红）再实现（绿）；UI 组件实现后补关键交互测试
- **手工回归清单**：每 Phase 验收标准即回归清单

## 风险与对策

| 风险 | 对策 |
|------|------|
| ~~`@crxjs/vite-plugin` 滞后最新 Vite~~ | ✅ Phase 0 已触发并解决：crxjs 2.7.1 在 Vite 8（rolldown 内核）下不生成 manifest、不注入入口 → 启用 **Plan B 手动构建**（静态 `public/manifest.json` + 显式 rollup 入口）。代价：无 HMR，开发用 `pnpm watch` + 刷新扩展页 |
| TypeScript 7（原生重构版）与 vue-tsc / typescript-eslint 不兼容 | ✅ 已锁定 `typescript@^5.9`（5.9.3），等生态跟上再升 |
| 商店对「新标签页」用途描述敏感 | 描述只谈书签展示/管理；零搜索字眼（已在范围中根除） |
| MV3 service worker 生命周期 | 项目无后台逻辑，manifest 可不带 background |
| 上传壁纸配额 | 压缩 + 仅存单张 + 溢出降级 |
| `backdrop-filter` 数量多时渲染开销（毛玻璃 × 大量卡片/多层弹窗） | 分层模糊（卡片轻、浮层重）；低性能设备降级开关（仅半透明）；Phase 4 实测 |
| Edge 审核周期波动 | 先提 Chrome，Edge 并行提交不阻塞 |
